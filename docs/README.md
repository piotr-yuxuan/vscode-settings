# Documentation

The documentation follows [Diataxis](https://diataxis.fr/): four kinds of page, each for one
need. Pick the kind that matches what you are doing, then the page. The configuration
itself is commented where it is written: [the settings](../user/settings.json) and
[the key bindings](../user/keybindings.json).

| Kind | Read it when you want to | Directory |
|---|---|---|
| Tutorial | learn, by doing a guided lesson | `tutorials/` |
| How-to | get a task done, and know what the task is | `how-to/` |
| Reference | look up a fact: a key, a word, a command | `reference/` |
| Explanation | understand why it is built this way | `explanation/` |

## Tutorials

- [Getting started](tutorials/getting-started.md): install the configuration on a Mac or on
  NixOS, with the tool or by hand, and run the tests.
- [A first day with this configuration](tutorials/first-day.md): a key check, then files,
  search, windows and git on a practice project.

## How-to guides

- [Work on a managed laptop](how-to/work-on-a-managed-laptop.md): what to ask before
  installing, what to do when an extension or the network is refused, and what to ask the
  team in the first week.

## Reference

- [Key bindings](reference/keybindings.md): every rule this configuration adds, generated
  from the source; do not edit it by hand.
- [Emacs to VS Code vocabulary](reference/emacs-to-vs-code-vocabulary.md): the VS Code word
  for each Emacs word, a colleague's shortcut translated, and what has no equivalent.
